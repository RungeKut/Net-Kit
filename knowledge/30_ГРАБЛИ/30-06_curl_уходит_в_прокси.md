# curl уходит в прокси

## Что происходит

В окружении задана переменная `http_proxy` (например, локальный прокси на
`127.0.0.1`). curl использует её молча.

Два следствия, оба плохие:

**1. Привязка к интерфейсу ломается.** curl пытается подключиться к
прокси на localhost с адресом источника из другой сети:

```
$ curl -sv --interface 192.0.2.10 http://example.com
* Uses proxy env variable http_proxy == 'http://127.0.0.1:8118'
* connect to 127.0.0.1 port 8118 from 192.0.2.10 port 53868 failed: Address not available
```

**2. Хуже: проверка «проходит».** Без привязки curl честно идёт через
прокси и возвращает `200`. Выглядит как доказательство, что сеть работает,
а на самом деле измерен путь через прокси, а не через исследуемый роутер.

## Как правильно

```
curl --noproxy '*' --interface 192.0.2.10 -o /dev/null -w "%{http_code}\n" http://example.com
```

`--noproxy '*'` в любой сетевой проверке, без исключений.

Проверить, есть ли ловушка на машине:

```sh
env | grep -i proxy
```

## Как неправильно

Считать `http=200` доказательством связности. Без `--noproxy` это
доказательство того, что жив прокси.

## Родственный случай

`ping`, `nslookup`, `tracert` прокси не используют — их результаты
этой ловушкой не искажаются. Поэтому при расхождении «ping идёт, curl
не идёт» или наоборот — первым делом смотреть переменные окружения.

## Чем подтверждено

`curl -sv` показал строку `Uses proxy env variable`; после добавления
`--noproxy '*'` та же команда с привязкой отработала и вернула 200,
а счётчики на роутере подтвердили прохождение трафика.

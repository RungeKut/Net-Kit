# Conntrack как доказательство

## Что происходит

Таблица отслеживания соединений заполняется в `prerouting` — **до** того,
как пакет попадёт в цепочки фильтра. Значит:

* **запись есть** → пакет физически дошёл до роутера;
* **записи нет** → пакет до роутера не добрался, и искать надо раньше:
  в маршрутизации на своей машине, в NAT по дороге, в криптомаршрутизации
  туннеля.

Запись создаётся даже если фаервол потом этот пакет отбросит.

```
/ip firewall connection print where src-address~"192.0.2.10"
/ip firewall connection print where protocol=icmp
/ip firewall connection print count-only
```

## Флаги, которые нужны

```
S - SEEN-REPLY    ответ получен
A - ASSURED       соединение устоялось
C - CONFIRMED     подтверждено
F - FASTTRACK     ушло в fastpath, фаервол больше не видит
s - SRCNAT        адрес источника подменён
```

**Главный из них — `S`.** Запись без `S` означает: пакеты ушли, ответа нет.
Вместе с нулевыми счётчиками `drop` это даёт однозначный вывод: роутер
пропустил, а не ответил кто-то другой.

## Приём: отличить «заблокировано» от «не ответили»

Пинг из изолированной сети в локальную не дал ответа. Два объяснения,
и они требуют разных действий.

```
/ip firewall filter print stats where chain=forward   → все drop = 0
/ip firewall connection print where src-address~"..."  → запись есть, флага S нет
```

Вывод: роутер **пропустил** трафик, хост просто не ответил своим
фаерволом. То есть изоляции нет, хотя на вид «не пингуется».

Обратный случай: записи нет вовсе — значит, пакет не дошёл. Так нашлась
криптомаршрутизация WireGuard, отбрасывающая пакеты по `allowed-address`
раньше всякого фаервола.

## Оговорка про fasttrack

Установленные соединения уходят в fastpath (флаг `F`) и **перестают
проходить через правила**. Новые правила действуют только на новые
соединения. Чтобы применилось сразу:

```
/ip firewall connection remove [find]
```

## Чем подтверждено

Запись `icmp 192.0.2.10 → 198.51.100.20`, 6 пакетов отправлено,
0 получено, ни один `drop` в forward не сработал; контрольная проверка
с другого адреса показала, что цель на ping отвечает.

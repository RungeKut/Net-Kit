# Бытовой роутер как клиент site-to-site

> Статус «не проверено» честный: сторона сервера измерена
> ([30-11](../30_ГРАБЛИ/30-11_туннель_поднят_но_трафик_не_идёт.md)),
> а настройки на клиенте применить не удалось — устройство недоступно
> ровно из-за описываемой проблемы. Применишь — обнови статус.

## Задача

Соединить две сети так, чтобы из каждой были видны устройства другой.
На стороне MikroTik это делается целиком (сервер L2TP, `/ppp secret`
с `routes=`, правила forward в обе стороны). На стороне бытового
роутера-клиента — **нет**: он поднимает туннель и на этом
останавливается.

## Три настройки, каждая нужна отдельно

### 1. Интерфейс туннеля — в доверенный сегмент

По умолчанию VPN-подключение недоверенное: входящие блокируются,
управление недоступно. Именно из-за этого не работает удалённое
администрирование.

Keenetic, веб-интерфейс: «Межсетевой экран» → выбрать интерфейс
подключения → разрешающие правила. Проще через CLI (SSH или
«Командная строка» в веб-интерфейсе):

```
show interface                       # узнать имя, например L2TP0
interface L2TP0 security-level private
system configuration save
```

`security-level private` переводит интерфейс в домашний сегмент:
входящие проходят, NAT на нём выключается.

### 2. Маршруты в удалённые сети

Сервер маршрут клиенту **не раздаёт** — у L2TP такого механизма нет.
Без маршрутов ответы уходят в интернет через шлюз по умолчанию.

«Маршрутизация» → «Добавить маршрут» → «Маршрут в сеть», интерфейс —
подключение VPN. По одной записи на каждую удалённую сеть.

### 3. Не использовать подключение для выхода в интернет

Галочка «Использовать для выхода в Интернет» уводит **весь** трафик
площадки в туннель. Для site-to-site её надо снять.

## Порядок проверки после настройки

Снизу вверх, каждый шаг отделяет причину:

```
1. сервер пингует адрес пира              → интерфейс стал доверенным
2. сервер пингует шлюз удалённой сети     → то же, другой адрес
3. сервер пингует хост в удалённой сети   → маршруты обратно есть
4. из удалённой сети пингуется твоя сеть  → маршруты туда есть
5. открывается веб-интерфейс клиента      → управление работает
```

Встало на шаге 1 — фаервол клиента. На шаге 3 — маршруты.
На шаге 4 — маршруты в обратную сторону.

## Чего это НЕ решает

**Третья площадка.** Если твои две сети связаны отдельным туннелем
(например WireGuard), трафик клиента до третьей сети не пойдёт, пока
её адрес не появится в `allowed-address` **обоих** пиров WireGuard.
Криптомаршрутизация отбрасывает чужой адрес источника до всякого
фаервола ([30-03](../30_ГРАБЛИ/30-03_изоляция_бывает_не_в_фаерволе.md)).

**Гостевая сеть клиента.** У бытовых роутеров она обычно уже
изолирована от домашней, но после перевода туннеля в доверенный сегмент
стоит проверить, что гости в туннель не попадают.

## Отдельно про пароль

Прежде чем открывать удалённое управление, сменить учётные данные
устройства. Заводской `admin/admin` за туннелем, ведущим в домашнюю
сеть, превращает чужую площадку в путь внутрь.

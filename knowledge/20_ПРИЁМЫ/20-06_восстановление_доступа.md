# Восстановление доступа

> Статус «не проверено» сознательный: доступ в этой работе ни разу не
> терялся, потому что всегда был второй путь
> ([20-01](20-01_два_пути_до_роутера.md)). Проверить эти шаги можно
> только на не боевом роутере — до того, как они понадобятся.

## Порядок

**1. Второй путь.** Резался доступ из локальной сети — пробовать через
туннель, и наоборот. Это то, ради чего он заводился.

**2. Кабель в свободный порт моста.** Не зависит от радио, но проходит
те же правила фильтра, что и Wi-Fi. Помогает при проблеме с точкой
доступа, не при ошибке в `input`.

**3. Winbox по MAC.** Вкладка Neighbors, выбрать строку с MAC вместо IP.
Работает на канальном уровне, когда IP уже не работает: адрес настроен
неверно, фаервол закрыл всё, подсети пересеклись. Только из той же
физической сети.

MAC бриджа записывать в карту площадки заранее — искать его будет негде.

**4. Safe Mode** — если консоль ещё отвечает. `Ctrl+X` включает, второй
`Ctrl+X` применяет. Обрыв связи откатывает все изменения сеанса.
Включать **до** правки правил, а не после.

**5. Сброс с импортом** — последнее средство:

```
/system reset-configuration no-defaults=yes skip-backup=no run-after-reset=backup.rsc
```

Роутер перезагрузится с чистого листа и накатит файл. Значит, файл должен
быть **уже на роутере**, залитый заранее:

```sh
scp backup.rsc user@192.0.2.1:
```

Физически — кнопка Reset при подаче питания.

## Почему импорт поверх работающего конфига ненадёжен

Полный `/export` — это набор команд `add`, а не описание желаемого
состояния. Применённый поверх существующей конфигурации, он создаёт
дубликаты правил и адресов вместо замены. Отсюда `run-after-reset`:
сначала чистый лист, потом импорт.

Выборочно — открыть `.rsc` редактором, найти нужный раздел и выполнить
команды вручную. Файл читаемый.

## Таблица «симптом → куда смотреть»

| Симптом | Наиболее вероятная причина | Чем проверить |
|---|---|---|
| Нет интернета ни у кого, включая роутер | аплинк | `/ping`, `/ip route print`, `/interface print` |
| Пинг по IP идёт, сайты не открываются | DNS ([30-01](../30_ГРАБЛИ/30-01_правило_без_in_interface_режет_своих.md)) | счётчики, искать дропы на порту 53 |
| Клиент не получает адрес | правило в `input` режет DHCP | счётчик разрешающего правила, `/ip pool print` |
| Интернет только у части сетей | `masquerade`, списки интерфейсов | `/ip firewall nat print`, `/interface list member print` |
| Изолированная сеть видит локальную | правило на список или его позиция | `print where chain=forward`, счётчики |
| Клиенты видят друг друга | `horizon`, `default-forwarding` | `/interface bridge port print` |
| Wi-Fi рвётся раз в минуту | часто следствие, а не причина | сначала проверить DNS и интернет |
| Роутер недоступен из локальной сети | лишний `drop` в `input` | зайти вторым путём, `print where chain=input` |

## Если правило не работает, хотя выглядит правильным

Три причины по частоте:

1. **Позиция** — выше стоит правило, поймавшее пакет раньше
   ([30-08](../30_ГРАБЛИ/30-08_позиция_правила_важнее_условий.md)).
2. **Списки интерфейсов** — нужный интерфейс не добавлен в `LAN`/`WAN`.
3. **Fasttrack** — установленные соединения ушли в fastpath и правил
   больше не видят. Применить сразу: `/ip firewall connection remove [find]`.

И всегда счётчики: ноль на правиле, которое должно срабатывать, означает,
что до него не доходит.

## Самые опасные изменения

Перед ними — Safe Mode и второй путь:

* любое `drop` в цепочке `input`;
* изменение списков `LAN` / `WAN`;
* смена адреса на интерфейсе, через который подключён;
* `/system reset-configuration`.

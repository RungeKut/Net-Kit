# Net-Kit

Набор для работы с сетями MikroTik RouterOS скриптами: диагностика,
фаервол, гостевые и IoT-сети, Wi-Fi, туннели между площадками.

Устроен как скилл для Claude Code плюс база знания, накопленного опытом.
Оформлен по образцу [MCU-Kit](../MCU-Kit).

```
Net-Kit/
  skill/SKILL.md     что читает ИИ, когда берётся за сеть
  knowledge/         база: как вызывать, как работать, что ломается
  netkit/            библиотека: ros, probe, wifi
  local/             карты конкретных сетей — НЕ под git
  tools/             проверки перед коммитом, установка
```

## Установка

Двойной клик по `Install-skill.bat`. Прав администратора не нужно.

Скрипт создаёт junction `~/.claude/skills/net` → `<корень>/skill`,
заводит локальный стоп-лист, включает хук `commit-msg` и проверяет,
что автор коммитов задан для клона.

После установки скилл доступен как `/net` и подхватывается сам, когда
речь заходит о роутере, фаерволе, гостевой сети или Wi-Fi.

## Что нужно на машине

| Что | Зачем |
|---|---|
| OpenSSH 8.4+ | пароль из скрипта через `SSH_ASKPASS` |
| PowerShell 5.1 | проверки TCP и DNS с привязкой к источнику |
| Python 3.x | библиотека и проверки набора |
| curl, Git Bash | HTTP-проверки, оболочка |

Прав администратора не требуется — приёмы подобраны так, чтобы работать
без них. Подробности: `knowledge/40_СРЕДА/40-01`.

## Главный принцип: сеть — общий ресурс

Ошибка в микроконтроллере стоит перепрошивки. Ошибка в фаерволе оставляет
без связи людей, которые об этом не просили, и может отрезать тебя самого
от роутера на другой площадке.

Отсюда три обязательных шага перед любым изменением правил:

1. **Второй независимый путь до роутера** — уже проверенный.
2. **`/export`, забранный к себе** — до первой правки.
3. **Понять, свой это роутер или общий.** На общем — только с явного
   согласия человека.

## Второй принцип: осмотр начинается с /export

Не с серии `print`. Серия `print` показывает только то, что ты решил
спросить, и раздел, о существовании которого не думаешь, остаётся
невидимым.

На реальном роутере вся изоляция гостевой сети держалась на
`/routing rule` — в `/ip firewall ...` этого не видно никогда. Вывод
«изоляции нет» был сделан по чтению фаервола и оказался неверным.
Одна команда `/export`, сделанная первой, сняла бы вопрос.

## Третий принцип: измерять, а не рассуждать

Счётчики правил и таблица соединений отвечают на вопросы, на которые
чтение конфига ответить не может:

* счётчик `drop` растёт — правило режет, вот причина;
* все `drop` по нулям, а трафик был — значит **разрешено**, а не
  «трафика не было»;
* запись в conntrack есть, ответа нет — пакет дошёл, отвечать некому;
* записи нет вовсе — пакет не дошёл, искать надо раньше.

И отдельно: **отрицательный результат без контрольного опыта не
доказывает ничего.** «Не пингуется» может значить и «защита работает»,
и «там никого нет». Нужна пара измерений.

## База знаний

`knowledge/INDEX.md` — плоская карта, читается целиком. Заголовки
сформулированы утверждениями, поэтому ответ часто виден уже оттуда.

| Раздел | О чём |
|---|---|
| `10_API` | как вызывать: SSH, `/export`, счётчики, conntrack |
| `20_ПРИЁМЫ` | как работать: два пути, порядок поиска, проверка из нужной сети, контрольный опыт, четыре уровня изоляции |
| `30_ГРАБЛИ` | что ломается: каждая запись — потерянный час |
| `40_СРЕДА` | установка, репозиторий, данные площадок |

Правила ведения базы — `knowledge/00_ПРАВИЛА.md`. Читаются первыми при
любом изменении документации. Коротко:

* запись без `verified` не имеет силы;
* `title` — утверждение, а не тема;
* `applies_to` обязано называть версию RouterOS и модель;
* «проверено» на другой версии читается как «не проверено»;
* дубликат хуже пробела;
* удалять нельзя, можно пометить `устарело`.

## Библиотека

```python
import os, sys
sys.path.insert(0, os.environ["NETKIT_HOME"])
import netkit as nk
from netkit import probe, wifi

with nk.Router("192.0.2.1", user="admin", pw_file="local/pw.txt") as r:
    print(r.version())              # модель и версия — для applies_to
    path = r.export("osmotr")       # выгрузка к себе + удаление с роутера
    r.reset_counters()
    print(r.counters(chain="input"))
    print(r.connections('protocol=icmp'))

probe.ping("192.0.2.10", "8.8.8.8")             # с привязкой к источнику
probe.tcp ("192.0.2.10", "192.0.2.1", 22)
probe.dns ("192.0.2.10", "8.8.8.8")
probe.http("192.0.2.10", "http://example.com")  # --noproxy обязателен
probe.route_to("8.8.8.8")                       # куда реально пойдёт пакет
```

| Модуль | Что в нём |
|---|---|
| `ros` | `Router`: `cmd`, `export`, `counters`, `reset_counters`, `connections`, `version` |
| `probe` | `ping`, `tcp`, `dns`, `http`, `route_to`, `addresses` |
| `wifi` | `networks`, `add_profile`, `connect`, `disconnect`, `delete_profile`, `address`, `current` |

Все функции проверены на живом роутере. Знание, лежащее в основе
функции, продублировано в её docstring со ссылкой на запись базы.

## Данные площадок — в local/, не под git

Репозиторий публичный, а схема сети — готовая карта для того, кто будет
её ломать. В набор не попадают адреса, публичные IP, SSID и пароли,
логины, ключи, MAC-адреса, имена людей и устройств, пробросы портов.

Реальные карты сетей живут в `local/` под `.gitignore`. Признак, по
которому отличить одно от другого:

> запись, из которой нельзя убрать конкретные адреса, не сломав смысл, —
> не знание, а данные площадки.

Образец карты — `local/ПЛОЩАДКА-образец.md`.

**Пароли не кладутся даже в `local/`.** Файл с паролем создаётся на время
работы и удаляется после. Правильнее — SSH-ключи:

```
/user ssh-keys import public-key-file=id_rsa.pub user=<логин>
```

## Перед коммитом

```bash
git diff                      # прочитать глазами
python tools/check_docs.py    # индекс, шапки, утечки, git
git add -A && git commit -m "кратко что и почему"
git push
```

`check_docs.py` ловит слова из стоп-листа, адреса вне документационных
диапазонов, MAC-адреса, строки, похожие на ключи, и файлы `local/`,
попавшие в индекс git. Хук `commit-msg` проверяет то же в тексте коммита.

Проверка **не ловит** описание, по которому площадка узнаётся без единого
адреса. За этим — `git diff` глазами.

При написании базы проверка сразу поймала три настоящие утечки в свежих
записях: реальную сеть в примере WireGuard, MAC соседа и пару
пересекающихся подсетей. Она работает.

## Обновление набора по ходу работы

* Поведение разошлось с ожиданием и причина найдена — **сразу** запись
  в `knowledge/30_ГРАБЛИ`, строка в `INDEX.md`, строка в `CHANGELOG.md`.
* Функция полезна не только этой сети — в `netkit`.
* **Изменил сеть — в тот же заход обнови карту в `local/`.**
* Одно изменение часто даёт две записи: данные в `local/`, обезличенное
  знание в `knowledge/`.
* После любой правки — коммит и `git push`.
